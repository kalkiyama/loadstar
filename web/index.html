Test mode
Load — hold a steady level: “can we handle Black Friday?” · Stress — keep climbing until it breaks: “where is the ceiling?” · Spike — sudden burst: “what if we hit the front page?” · Soak — long and steady: “do we leak memory over hours?”
Test data — CSV file (optional)

Upload a CSV where the first row names your columns, e.g. username,password. Then use ${username} anywhere in the URL, headers, or body — each virtual user picks the next row automatically.

Pass/fail thresholds — for CI/CD (optional)

If any threshold is exceeded, the run is marked SLA failed — your CI pipeline can read that flag and block the deploy (see ci/ in the project).

Steps — what should the user do?

The test always starts by opening your Target URL. Then each step runs in order. A selector points at something on the page — the easiest kind is text=Sign in (finds whatever says "Sign in"). See the Browser testing guide in the project folder for a friendly walkthrough.

Check steps verify the page is actually right — not just that your clicks worked. Without them a flow can click straight through a completely broken page and still pass. Add Check: text is NOT there with Error after a checkout step to catch exactly that.
